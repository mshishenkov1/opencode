# Тесты раскладки корп-окон (BUG-I10-002)

Тест, который **считает геометрию**, а не читает исходник. Появился после `BUG-I10-002`: витрина
коннекторов в собранном приложении показывала пустую таблицу — `TabsV2` с `height: 100%` занимал всю
панель, список схлопывался в ноль, поиск и шапка уезжали за нижний край, — и при этом все 541 тест
`packages/app` были зелёными. Прежнее покрытие витрины проверяло текст исходника и разрешимость
CSS-переменных в happy-dom, который раскладку не считает; поймать элемент, занявший всё окно, оно не
могло по построению.

## Что здесь лежит

| Файл | Что делает |
|---|---|
| `fixture/shell.tsx` | оболочка витрины: настоящие `Dialog`/`DialogV2` в той же обёртке Kobalte, какой их монтирует `packages/ui/src/context/dialog.tsx`, настоящие `TabsV2` и `List`, настоящие стили приложения (`@/index.css`) и корп-`dialog-shell.css`. Своего CSS фикстура не добавляет ни строки |
| `fixture/vite.config.ts` | сборка фикстуры **теми же плагинами**, что у приложения (`packages/app/vite.js`): алиас `@`, tailwind, `vite-plugin-solid`. Формат `iife` — одним файлом, чтобы тесту не был нужен ни dev-сервер, ни сервер opencode |
| `connectors-layout.layout.test.ts` | измерение: 21 сценарий — обе ветки флага оформления × 0/1/50 карточек, шесть пустых состояний, баннер с предупреждением, проверка соответствия фикстуры разметке витрины |
| `playwright.config.ts` | своя конфигурация без `webServer` (основная `packages/app/playwright.config.ts` поднимает dev-сервер и ждёт сервер opencode) |

## Как гонять локально

```
bun --cwd packages/app run test:layout
```

Фикстура собирается автоматически в `test.beforeAll`; отдельного шага сборки нет.

**Браузер.** По умолчанию берётся chromium, установленный `playwright install chromium`. Если его
нет, а в системе есть Google Chrome, конфигурация переключается на него каналом `chrome` — скачивать
ничего не нужно. Канал можно задать явно: `PLAYWRIGHT_CHANNEL=chrome bun --cwd packages/app run test:layout`.

## Как гонять в CI

`corp-ci.yml` идёт на `ubuntu-latest` через `./.github/actions/setup-bun`; браузеров Playwright там
нет, поэтому нужен отдельный шаг установки — иначе задание упадёт на запуске браузера, а не на
раскладке. Шаг для задания `checks`, сразу после «Тесты packages/app»:

```yaml
      - name: Браузер для тестов раскладки
        run: bun x playwright install --with-deps chromium

      - name: Тесты раскладки корп-окон (packages/app)
        run: bun run --cwd packages/app test:layout
```

`--with-deps` ставит системные библиотеки, без которых headless chromium на ubuntu-раннере не
стартует. Шаг занимает около минуты на скачивание браузера; кэшировать его можно
`actions/cache` по пути `~/.cache/ms-playwright`.

Правку `.github/workflows/corp-ci.yml` вносит тот, кому это разрешено ролью: test-agent
`.github/` не правит. До тех пор тест гоняется локально и его прогон фиксируется в отчёте итерации.

## Доказательство фальсифицируемости

Тест обязан ловить ровно тот дефект, ради которого написан. Проверено откатом фикса `b2574261da`:
в `packages/app/src/components/corp/dialog-shell.css` правило вкладок возвращено к состоянию до
фикса (`flex: none`, без `height: auto`).

```
21 passed                       # с фиксом
15 failed, 6 passed             # с откаченным фиксом
```

Первое же падение называет причину дословно: «вкладки выше разумного предела в 48px, получено
510.2» — то самое, что видел пользователь. После проверки файл восстановлен побайтово
(`git status` по нему пуст).
