# Тесты раскладки корп-окон (BUG-I10-002)

Тест, который **считает геометрию**, а не читает исходник. Появился после `BUG-I10-002`: витрина
коннекторов в собранном приложении показывала пустую таблицу — `TabsV2` с `height: 100%` занимал всю
панель, список схлопывался в ноль, поиск и шапка уезжали за нижний край, — и при этом все 541 тест
`packages/app` были зелёными. Прежнее покрытие витрины проверяло текст исходника и разрешимость
CSS-переменных в happy-dom, который раскладку не считает; поймать элемент, занявший всё окно, оно не
могло по построению.

## Что здесь лежит

| Файл | Что делает |
|---|---|
| `fixture/shell.tsx` | оболочка витрины: настоящие `Dialog`/`DialogV2` в той же обёртке Kobalte, какой их монтирует `packages/ui/src/context/dialog.tsx`, настоящие `TabsV2` и `List`, настоящие стили приложения (`@/index.css`) и корп-`dialog-shell.css`. Своего CSS фикстура не добавляет ни строки |
| `fixture/vite.config.ts` | сборка фикстуры **теми же плагинами**, что у приложения (`packages/app/vite.js`): алиас `@`, tailwind, `vite-plugin-solid`. Формат `iife` — одним файлом, чтобы тесту не был нужен ни dev-сервер, ни сервер opencode |
| `connectors-layout.layout.test.ts` | измерение: 20 сценариев — обе ветки флага оформления × 0/1/50 карточек, пять пустых состояний (S-V12, ревизия 1.12), баннер с предупреждением, две проверки соответствия фикстуры разметке витрины |
| `playwright.config.ts` | своя конфигурация без `webServer` (основная `packages/app/playwright.config.ts` поднимает dev-сервер и ждёт сервер opencode) |

## Как гонять локально

```
bun --cwd packages/app x playwright test --config test-layout/playwright.config.ts
```

Фикстура собирается автоматически в `test.beforeAll`; отдельного шага сборки нет.

Скрипта в `packages/app/package.json` намеренно нет: `package.json` — upstream-файл, и строка в нём
потребовала бы записи в реестре правок `corp/patches.md` (S-B6, S-C8). Ради удобства запуска платить
следом в upstream не стоит — команда выше одна и та же локально и в CI. По той же причине результаты
Playwright кладутся в `fixture/dist/test-results`: `dist` уже игнорируется корневым `.gitignore`.

**Браузер.** По умолчанию берётся chromium, установленный `playwright install chromium`. Если его
нет, а в системе есть Google Chrome, конфигурация переключается на него каналом `chrome` — скачивать
ничего не нужно. Канал можно задать явно: `PLAYWRIGHT_CHANNEL=chrome bun --cwd packages/app x playwright test --config test-layout/playwright.config.ts`.

## Как гонять в CI

`corp-ci.yml` идёт на `ubuntu-latest` через `./.github/actions/setup-bun`; браузеров Playwright там
нет, поэтому нужен отдельный шаг установки — иначе задание упадёт на запуске браузера, а не на
раскладке. Шаг для задания `checks`, сразу после «Тесты packages/app»:

```yaml
      - name: Браузер для тестов раскладки
        run: bun x playwright install --with-deps chromium

      - name: Тесты раскладки корп-окон (packages/app)
        run: bun --cwd packages/app x playwright test --config test-layout/playwright.config.ts
```

`--with-deps` ставит системные библиотеки, без которых headless chromium на ubuntu-раннере не
стартует. Шаг занимает около минуты на скачивание браузера; кэшировать его можно
`actions/cache` по пути `~/.cache/ms-playwright`.

Правку `.github/workflows/corp-ci.yml` вносит тот, кому это разрешено ролью: test-agent
`.github/` не правит. До тех пор тест гоняется локально и его прогон фиксируется в отчёте итерации.

## Доказательство фальсифицируемости

Тест обязан ловить ровно тот дефект, ради которого написан. Проверено откатом фикса `b2574261da`:
в `packages/app/src/components/corp/dialog-shell.css` правило вкладок возвращено к состоянию до
фикса (`flex: none`, без `height: auto`).

```
21 passed                       # с фиксом (счёт на момент проверки — до ревизии 1.12 EMPTY_STATES)
15 failed, 6 passed             # с откаченным фиксом
```

Первое же падение называет причину дословно: «вкладки выше разумного предела в 48px, получено
510.2» — то самое, что видел пользователь. После проверки файл восстановлен побайтово
(`git status` по нему пуст).

## Сторож фикстуры (разбор фикстуры, микроревизия после 1.12.1)

До этой правки набор был 21 зелёный тест и при этом ничего не охранял: `fixture/shell.tsx` рисовал
собственной захардкоженной разметкой три вкладки («Все» / «Подключённые» / «Неподключённые») и
двустрочную строку каталога (имя + `alias` отдельной строкой), хотя настоящая витрина
(`dialog-connectors.tsx`) после ревизии 1.12 (D-53) рисует две вкладки и однострочную строку. Прежняя
проверка «фикстура повторяет разметку витрины» подтверждала только присутствие нужных подстрок
(`toContain`) — она не видела того, чего в исходнике уже не было, и лишняя вкладка/строка проходила
незамеченной.

Добавлен второй тест с тем же названием-темой — «вкладки и однострочный ряд вычислены из
исходника» — который вычисляет ожидание **из текста `dialog-connectors.tsx` регулярным выражением
при каждом прогоне**, а не хранит вторую копию тех же литералов:
  - набор и порядок `value` каждого `<TabsV2.Trigger>` в фикстуре обязан **дословно** совпасть с
    таким же списком, извлечённым из исходника;
  - класс первого `<div>` сразу после `data-slot="corp-connectors-row"` (однострочная обёртка
    `flex items-center …` против прежней `flex flex-col …`) обязан совпасть тоже;
  - число `resetFilter`-пустых состояний в `EMPTY_STATES` этого файла обязано равняться числу
    филируемых вкладок исходника (все, кроме «Все»).

Доказано инъекцией (без веб-сервера, только `bun x playwright test … -g "вкладки и однострочный
ряд"`): временный откат `fixture/shell.tsx` к прежней трёхвкладочной разметке —
`Error: набор вкладок фикстуры разошёлся с исходником`; временный откат строки каталога к
двустрочной — `Error: обёртка ряда в фикстуре разошлась с исходником (однострочность/flex-col)`.
Оба раза причина названа явно, оба раза файл восстановлен обратно
(`git status` по нему пуст после проверки). Заодно из `EMPTY_STATES` убрано шестое состояние
«Подключено всё» — пустое состояние вкладки «Неподключённые», которой в приложении больше нет
(снижает счёт сценариев до 20).
